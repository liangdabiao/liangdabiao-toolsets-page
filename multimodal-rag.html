为什么做这个？

传统RAG的局限，用多模态视觉理解来突破

📄 传统RAG的痛点

传统RAG系统需要将PDF进行文本提取和OCR处理，面对扫描件PDF、图文混排文档、含公式与表格的专业资料时，文本提取往往丢失大量关键信息——表格结构被破坏、图表信息完全丢失、排版语义无法保留、手写批注被忽略。本系统跳过文本提取，直接将PDF页面当作图片向量化，由视觉大模型直接"看图"回答，完整保留所有视觉信息。

核心处理步骤

1. PDF转图片
使用PyMuPDF (fitz) 将PDF每页转为150 DPI图片，纯Python实现，无需poppler，跨平台直接可用。
2. 视觉Embedding编码
通过云端多模态Embedding API对每页图片编码，Cohere输出1024维向量，DashScope输出1152维向量，每页图片对应1个向量。
3. 向量存储与检索
将doc_name + page_idx + vector写入Zilliz Serverless云向量数据库，使用IVF_FLAT索引和内积相似度进行Top-K搜索。
4. 视觉大模型生成
将检索到的最相关页面原始图片与用户问题一起发送给视觉大模型（Qwen系列），AI直接"看图"生成回答。

安装与配置

简单几步，开始PDF智能问答

1. 克隆项目

获取项目代码：

git clone https://github.com/liangdabiao/Multimodal-RAG.git
cd Multimodal-RAG
2. 安装依赖

仅需9个轻量Python包，无需PyTorch：

pip install -r requirements.txt
3. 配置环境变量

复制配置模板并填写密钥：

cp .env.example .env
# 编辑 .env 文件，填写以下配置：
# EMBED_PROVIDER=cohere        # 或 dashscope
# LLM_PROVIDER=dashscope       # 或 openrouter
# COHERE_API_KEY=your_key
# DASHSCOPE_API_KEY=your_key
# ZILLIZ_URI=your_zilliz_uri
# ZILLIZ_TOKEN=your_zilliz_token
4. 启动Web服务

启动Flask Web服务：

python app.py
# Web界面访问: http://localhost:7860
5. 启动API服务（可选）

启动独立API服务供外部调用：

python api_server.py
# API服务: http://localhost:7861
# 查询接口: POST /api/query
# 文档列表: GET /api/docs
6. API调用示例

使用curl调用查询接口：

curl -X POST http://127.0.0.1:7861/api/query \
  -H "Content-Type: application/json" \
  -d '{"question": "文档的主要内容是什么？"}'

常见问题

关于多模态RAG系统的常见疑问

Q: 需要本地GPU吗？
A: 完全不需要。所有AI计算（Embedding编码和LLM生成）均通过云端API完成，无需安装PyTorch或任何GPU驱动。
Q: 国内用户推荐使用哪个引擎？
A: 国内用户推荐全部使用DashScope（Embedding + LLM），无需代理，直接可用。海外用户可以使用Cohere Embedding和OpenRouter LLM。
Q: 支持哪些类型的PDF？
A: 支持所有类型的PDF，包括扫描件PDF、图文混排文档、含公式与表格的专业资料。因为系统直接将页面作为图片处理，不依赖文本提取和OCR。
Q: Zilliz云数据库如何配置？
A: 注册Zilliz Cloud账号，创建Serverless集群，获取URI和Token，填入.env配置文件即可。Zilliz Serverless提供免费额度。
Q: 如何切换Embedding和LLM引擎？
A: 通过.env文件中的EMBED_PROVIDER和LLM_PROVIDER环境变量独立切换。Embedding支持cohere和dashscope，LLM支持dashscope和openrouter。
