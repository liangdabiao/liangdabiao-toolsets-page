项目概述

Flue 是基于 harness-driven 架构的 TypeScript AI Agent 框架

📚 项目定位

Flue 不是另一个 AI SDK，而是一个真正的运行时无关框架——就像 Astro 或 Next.js，但专为 Agent 设计。一次编写，构建后可部署到任何地方（Node.js、Cloudflare、GitHub Actions、GitLab CI/CD 等）。

🏗️

框架层设计

Flue 回答的问题是："我怎么用一个框架把 agent 的定义、沙箱、session、部署形态标准化？"

⚡

无头运行

像 Claude Code，但 100% 无头（headless）且可编程。No TUI. No GUI. Just TypeScript.

🔄

模型无关

不绑定特定模型，支持 Anthropic、OpenRouter、Moonshot 等多种模型提供商。

🎯

沙箱抽象

将沙箱策略做成框架的一等可换层，从虚拟沙箱到容器沙箱渐进升级。

Flue vs Claude Agent SDK

架构、差异与选型对比

维度 Flue Claude Agent SDK
本质 Agent Harness / 框架（怎么定义/隔离/部署 agent） Claude Code CLI 的可编程包装（获得 Claude 级自主 agent 运行时）
开源/厂商 Apache-2.0，社区（withastro） Anthropic 官方；TS 包封装闭源 CLI（Python 版开源）
模型绑定 倾向模型无关（Anthropic/OpenRouter/…） Claude-only
Agent Loop TypeScript 框架内（你能看到 session 对象） Claude Code CLI 子进程内部（你通过 IPC 观察）
沙箱 一等抽象：virtual（just-bash）/ local / container cwd + permission + hooks；强隔离靠外层容器
内置工具 bash/shell 子集（virtual 模式） 极其完整：Read/Write/Bash/Grep/Glob/WebSearch
MCP 有，但 V1 不完整 原生、成熟、多模式
部署广度 Node / Cloudflare Edge / CI 需要能跑 CLI 的宿主；或 Managed Agents
成熟度 Experimental（API 会变） 生产可用（但架构约束明确）

Flue 三层沙箱策略

从轻量级到强隔离，按需选择

🎮 Virtual Sandbox（默认）
just-bash：在宿主环境模拟一个受限的文件视图 + bash 命令子集（grep/glob/read），不开容器。适合高并发、短命任务、知识库检索、翻译、分类——大幅更快更便宜。
💻 Local Sandbox
mount 宿主机文件系统，把特权 CLI（gh/git/npm）连进来，但不泄漏密钥。适合 CI/CD triage agent。
🐳 Container Sandbox（opt-in）
通过 connectors 接 Daytona / E2B / Modal 等。适合需要编译、浏览器、强隔离、原生二进制的任务。

⚡ 虚拟沙箱的优势

虚拟沙箱比每请求起容器快得多、便宜得多、可扩展性高得多，非常适合高流量 agent。对于绝大多数轻量级自主任务（检索、翻译、分类、KB问答），虚拟沙箱完全够用。

核心抽象链

Flue 的架构设计理念

Agent Definition (.flue/agents/*.ts)
→ Skills / Context / AGENTS.md（Markdown 承载行为）
→ Sandbox（virtual just-bash 默认 / 可选容器 via connectors）
→ Session（消息历史 + 状态）
→ 结构化输出（valibot schema → 运行时校验 → 类型安全返回值）
📝

Agent Definition

在 .flue/agents/ 目录下定义 agent，使用 TypeScript 描述 agent 的行为和能力。

📚

Skills / AGENTS.md

用 Markdown 承载 agent 的行为定义，repo-as-control-plane，便于版本控制和协作。

🔒

Sandbox

可配置的沙箱策略，从虚拟沙箱到容器沙箱按需选择。

💾

Session

管理消息历史和状态，支持持久化和恢复。

选型决策树

如何选择适合你的框架

✅ 选择 Flue 当——

• 你在 TypeScript 全栈团队，agent 要成为你产品的一部分
• 你需要 agent 跑在 Cloudflare Edge / 轻量 Node，不是每台机器起容器
• 你的很多 agent 任务是"轻量自主"（检索、翻译、分类、KB问答）
• 你想 agent 行为用 Markdown（skills/AGENTS.md）管理，靠近代码库版本控制
• 模型灵活（今天 Claude，明天 Kimi/K2/GPT）
• 你能接受 Experimental（API 会变，升级要跟）

✅ 选择 Claude Agent SDK 当——

• 你的核心诉求是："我要 Claude 级别的自主编码/文件操作 agent 嵌进我服务"
• 你接受子进程 + 磁盘状态的部署模型
• 模型绑定 Claude 不是问题（甚至是优势）
• 你需要内置 Read/Write/Bash/Grep/Glob/WebSearch 全套开箱
• 你需要成熟 MCP 集成 + hooks + permission 粒度
• 或者你直接走 Managed Agents（Beta），让 Anthropic 管沙箱/基础设施
