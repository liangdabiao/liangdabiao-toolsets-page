为什么做这个？

传统 PDF 问答方案的痛点，需要视觉 RAG 来突破

📄 传统 PDF 问答方案的痛点

给 PDF 提问，市面上有几条路但都不完美：A 方案每次把整本 PDF 塞给模型，单次就要数万图片 token、几十秒响应；B 方案传统文本 RAG 只搜文字，看不懂图表/扫描件，页码引用常常错误；C 方案 PageIndex 只生成目录树、没有问答，靠模型猜+修复循环。本 skill 用"视觉阅读 + 三层漏斗检索"，让模型真正看页面图作答，页码来自物理事实天然精确，每次提问仅 2 次 API 调用、秒级响应。

核心功能

从建立索引到跨页召回，让 AI 真正读懂每一页

👁️

逐页视觉阅读

将 PDF 每页渲染为图片上传至 DeepSeek 文件服务器，视觉模型逐页"阅读"，能看懂图表、表格、代码块、公式，而不只是认字

📑

读书卡片索引

每页生成一张 JSON 卡片记录标题、摘要、关键词，120 张卡片 + 每页文字层 + 全书大纲一起存进缓存，一次建立永久复用

🎯

三层漏斗检索

本地 TF-IDF 粗筛 12 页(零费用) → 模型看图确认挑 4 页(关推理) → 推理深读作答(开推理)，便宜方法粗定位、贵的眼睛做确认

📍

天然精确页码

每张图就是"第 N 页"渲染出来，卡片标注 [第N页] 后交模型，页码来自物理事实不需要模型猜，章节定位与人工核对完全吻合

🔍

跨页召回

"审批策略"能找齐分散在 p5/6/14/15/16 的全部 5 处提及，跨页召回所有相关页，不让答案遗漏

📊

扫描版 PDF 支持

索引靠视觉阅读，扫描版纯图片无文字层也能用；本地粗筛更依赖摘要/关键词，通常多一两秒精排兜底，准确性不受影响

🖼️

自包含 HTML 预览

每次回答生成自包含 HTML 预览页，答案 + 全部引用页原图内嵌其中，双击浏览器打开即可查看，无需联网

💡

成本极低

建索引 5 次批量调用 + 120 次上传约 4.6 万 token 一次性付费；提问仅 2 次调用约 0.6~1.5 万 token；看指定页 0 次调用纯本地渲染

两阶段工作原理

阶段一：读一遍书，做笔记（ingest，一次性）
PDF 渲染为每页一张图片 → 上传 DeepSeek 文件服务器 → 视觉模型逐页阅读（25 页打包进 1 个请求，吃满 100 万 token 上下文）→ 生成 index.json 读书卡片。模型每读一页写一张卡片记录标题、摘要、关键词，120 张卡片 + 每页文字层 + 全书大纲一起存进缓存。从此这本书被"读过了"，永远不用再做。
阶段二：按笔记翻书，回答问题（ask，每次提问）
  • ① 查卡片：本地在 index.json 用 TF-IDF 关键词打分筛出最可能 12 页（毫秒级，零费用）
  • ② 看图确认：模型看这 12 页截图，挑出真正相关的 4 页（第 1 次 API 调用）
  • ③ 深读作答：这 4 页 ± 前后邻页原图摊开，开推理模式仔细读（第 2 次 API 调用）
  • 输出：答案（每个论点标 [第N页]）+ 引用页图片 + 自包含 HTML 预览
TF-IDF 本地检索细节
中文按二字滑窗分词（"审批策略"→审批/批策/策略），英文按整词取，去停用词；每页文档 = 标题/摘要/关键词各重复 3 遍 + 整页文字层 1 遍（权重×3）；打分 = Σ 词稀有度(idf) × min(出现次数,8)，idf 让稀有词值钱、次数封顶 8 防霸榜。
为什么页码天然精确
每张图片就是"第 N 页"渲染出来的，卡片上标注 [第N页] 标签后交给模型——页码来自物理事实，不需要模型猜。PageIndex 项目 80% 代码花在"让文字模型猜章节页码 → 验证 → 修复"上，本方案让这个环节整体不存在。

安装与配置

简单几步，开始 PDF 视觉问答之旅

1. 安装依赖

本机一般已装好 pip 包：

pip install openai pymupdf
2. 配置 API Key（可选）

API key 默认内置；可用环境变量覆盖：

export DEEPSEEK_API_KEY="你的密钥"
3. 建立索引（每份 PDF 一次）

120 页约 2~3 分钟；重复运行命中缓存瞬间返回：

python scripts/ingest.py "你的文件.pdf"
# 常用参数：
# --force       重建索引
# --limit 50    先索引前 50 页试水
# --clean       清缓存
4. 提问

输出答案、引用页、页面图片、HTML 预览四段：

python scripts/ask.py "你的文件.pdf" "审批策略出厂默认是什么？"
# 可调参数：--top 4 深读页数 | --cands 12 粗筛候选数 | --no-images 不出图片
5. 看指定页

高清渲染指定页，无需先建索引：

python scripts/show.py "你的文件.pdf" --pages 6,33 --dpi 220

常见问题

关于视觉 RAG 问答系统的常见疑问

Q: 索引建到一半断了或换电脑了，要重来吗？
A: 页图上传支持断点续传（files.json 记录进度），模型分析按批推进，重跑同一条命令会从断点继续。换电脑则服务端 file_id 仍在，只需拷走 .cache/ 目录。
Q: PDF 改了一个字，索引会更新吗？
A: 缓存键是 PDF 内容哈希，内容变了会自动另建新缓存，不会读旧索引。旧缓存可用 --clean 删（服务端文件配额 25GiB/1 万个，一般不用管）。
Q: 扫描版（纯图片、无文字层）能用吗？
A: 能。索引靠视觉阅读；只是本地粗筛少了文字层加持，会更依赖摘要/关键词，通常多一两秒精排兜底，准确性不受影响。
Q: 一本 500 页的书要建多久？
A: 大致线性外推：500 页约 10 分钟索引（21 次批量调用），之后每次提问仍是 2 次调用秒级响应。
Q: 为什么答案页码和 PDF 阅读器显示的有时差 1~2 页？
A: 本 skill 用物理页码（第 1 张图 = 第 1 页）。书有自己的印刷页码（正文从"第 1 页"起算），两者天然差一个前言偏移。答案统一按物理页码引用，展示的原图就是证据，不会有歧义。
