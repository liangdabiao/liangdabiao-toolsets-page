核心理念

传统编程与 LLM Agent 系统的优雅映射

💡 Skill 是程序，MCP 是库，LLM 是语言

Simple Agentic Stack 将传统编程范式映射到 AI Agent 世界：Skill（自然语言编写的执行步骤）就是程序， MCP Server（标准化工具接口）就是库，LLM（大语言模型）就是运行时语言。编排器作为胶水层， 将三者串联起来，驱动工具调用循环直到模型给出最终回答。

传统编程 Simple Agentic Stack 说明
程序（Program） Skill（Markdown） 自然语言编写的执行逻辑
库（Library） MCP Server 标准化工具接口，语义契约
语言（Language） LLM（DeepSeek 等） 理解指令、调用工具、生成回答
运行时（Runtime） 编排器（Orchestrator） 串联各组件，驱动执行循环

核心功能

8 项核心能力，构建完整的 AI Agent 编排体系

🔌

MCP 工具协议

基于 Model Context Protocol 标准化工具接口，每个 MCP Server 通过 @mcp.tool() 装饰器暴露工具，模型通过语义契约（函数名、docstring、类型注解）调用

📝

Skill 自然语言程序

Skill 不是普通 prompt，而是用自然语言编写的带执行逻辑的程序，明确告诉模型按什么步骤组合哪些工具，包含目的、可用工具、执行步骤三部分

🧠

LLM 智能运行时

支持 DeepSeek API 的 Anthropic 兼容接口，也兼容 OpenRouter、自部署 vLLM 等任何兼容 Anthropic Messages API 的服务端点

⚙️

编排器引擎

orchestrator.py 作为胶水层，读取配置拉起 MCP Server 子进程，收集工具定义转换 schema，注入 Skill 到 system prompt，运行工具调用循环

🔗

多数据源联动

同时对接外部 API（如公共假日查询）和本地数据库（如 SQLite 运维数据），完成跨数据源的复杂关联任务

🎯

配置驱动

通过 config.json 管理所有可变部分：换任务只需改 skill_path，换工具只需改 mcp_servers 条目，换模型只需改 .env，一行 Python 都不用动

🛡️

安全约束机制

max_steps 限制工具调用最大轮次，Skill 中定义硬约束和输出模板，确保 Agent 行为可控、结果可预期

🧪

独立测试支持

提供 server_test.py 独立验证 MCP Server 是否正常工作，可单独测试假日查询 Server 和运维数据库 Server

演示场景：值班假日检查

📋 场景描述

判断当前值班工程师所在国家今天是否有公共假日，若有则列出其名下的高优先级问题，以便安排备班人员。 Agent 需要同时查询运维数据库（获取值班信息）和外部假日 API（获取公共假日），再进行关联分析。

示例输出
=== 最终回答 ===

值班正常：Sara Chen（美国），今天是正常工作日。其名下的 P1 问题如下：
- #4 Auth token refresh fails for SSO users
- #1 API gateway returns 502 under load

安装与配置

简单四步，搭建本地 AI Agent 系统

1. 环境准备

创建虚拟环境并安装依赖：

python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
2. 配置 API 密钥

复制示例文件并填入 API 密钥：

cp .env.example .env

.env 文件内容：

ANTHROPIC_AUTH_TOKEN=your-api-key-here
ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
MODEL=deepseek-v4-flash
3. 初始化数据库

生成包含 5 名工程师、10 个轮班周期、12 条开放问题的测试数据库：

python seed_db.py
4. 运行系统

使用默认问题或指定自定义问题：

# 使用默认问题
python orchestrator.py

# 指定问题
python orchestrator.py "本周谁在值班？他们有没有 P0 问题？"
5. 测试 MCP Server（可选）

独立验证 MCP Server 是否正常工作：

# 测试假日查询 Server
python server_test.py

# 测试运维数据库 Server（需先 seed_db.py）
OPS_DB=./ops.db python server_test.py

常见问题

关于 Simple Agentic Stack 的常见疑问

Q: 支持哪些 LLM 提供商？
A: 默认使用 DeepSeek API 的 Anthropic 兼容接口，同时支持任何兼容 Anthropic Messages API 的服务端点，包括 OpenRouter、自部署 vLLM 等。只需修改 .env 中的 MODEL 和 ANTHROPIC_BASE_URL 即可切换。
Q: 如何添加新的 MCP Server？
A: 在 mcp_servers/ 目录下新建 Server 文件，使用 @mcp.tool() 装饰器暴露工具接口，然后在 config.json 的 mcp_servers 中添加一条配置即可。编排器会自动发现并加载新工具。
Q: 如何切换到完全不同的任务？
A: 只需三步：1) 编写新的 Skill（Markdown 文件）；2) 修改 config.json 中的 skill_path 指向新 Skill；3) 如需要，更新 mcp_servers 配置。一行 Python 都不用改。
Q: Skill 和普通 prompt 有什么区别？
A: Skill 不是普通 prompt，而是用自然语言编写的带执行逻辑的程序，包含三部分：目的（这个 Skill 做什么）、可用工具（列出所有工具及是否需要）、执行步骤 + 约束（明确的执行顺序、输出模板和硬约束）。
Q: 如何防止 Agent 无限调用工具？
A: config.json 中的 max_steps 参数限制了工具调用的最大轮次。同时在 Skill 中可以定义硬约束，确保 Agent 在有限步骤内给出最终回答。
