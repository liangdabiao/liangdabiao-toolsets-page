为什么做这个？

视觉模型没有"视频模态"，得自己造一个

🎬 视频理解的痛点

DeepSeek 视觉大模型并没有"视频模态"——实测把视频或 GIF 直接传过去，只会解码首帧（黑帧探针证实）， 根本无法理解时间维度的内容。要真正"看懂"视频，唯一可行的方式是按时间顺序抽帧成 JPEG 序列， 并在 prompt 中声明采样率与时间轴。本 Skill 就是把这套"抽帧建索引 → 按问题精读 → 带时间戳回答"的流程 封装成可复用的 Agent Skill：一次索引永久复用，回答带 [MM:SS] 引用，并切出可播放片段与关键帧供核对。

核心功能

从抽帧建索引到带时间戳回答与片段切出的全流程

🎞️

一次性视频索引

ffmpeg 抽帧 → 上传 → 视觉模型逐帧观看（25 帧/批）→ 生成 index.json 帧卡片与段卡片，从此该视频被"看过了"，不用再看第二遍全片。

⏱️

时间戳定位回答

答案带 [MM:SS] 时间戳引用，告诉你事件发生在第几分几秒，宏观 1fps 估计误差约 ±2s，便于直接跳转核对。

🔬

两级采样 + 微观升级

平时省着看（宏观 1fps），遇到瞄准/动作/瞬间类问题，自动对该时刻用 12fps + 中心放大重抽逐帧分析，补救 150ms 级瞬时事件。

✂️

可播放片段切出

对引用时刻自动切出前后 5 秒可播放片段（mp4），配合关键帧导出，让答案不止于文字，而是可直接播放核对。

🖼️

关键帧高清导出

用 show.py --at 01:23 高清渲染指定时刻帧图；--clip 切片段；--micro 生成 12fps 中心放大序列，灵活回看任意时刻。

📝

帧级 OCR 汇总

每帧提取可见文字（招牌/字幕/HUD），按帧卡片记录并汇总，回答"画面里出现过哪些文字"类问题。

📄

自包含 HTML 预览页

自动生成自包含 HTML 预览页，内嵌可播放片段 + 关键帧 + 答案，双击浏览器即看，单文件通常 5-15MB 便于分享。

📏

自适应采样密度

根据视频时长自动适配 fps：≤1 分钟 1fps、≤10 分钟 0.5fps、≤30 分钟 0.25fps、更长 0.1fps，长片也能低成本建宏观索引。

先读一遍做笔记，之后按笔记翻书

ffmpeg 抽帧
→

→

→

→
深读作答

两阶段原理与步骤

阶段一：看一遍做卡片（ingest，一次性）
视频经 ffmpeg 抽帧成按时间顺序的 JPEG 序列并上传到 DeepSeek 文件服务器；视觉模型逐帧观看（25 帧/批，prompt 声明采样率与时间轴），生成 index.json 帧卡片 + 段卡片 + 场景切换时间点。每帧 6 字段：场景、画面摘要、关键词、OCR、事件、运动强度。
阶段二：按卡片定位回答（ask，每次 2~3 次调用）
  • ① 查卡片：本地 TF-IDF 筛出最可能的段（毫秒级、零费用）
  • ② 看图确认：模型看候选段代表帧选出真正相关的段（1 次调用，关推理）
  • ③ 深读作答：选中段全部帧按时间轴摊开，开推理观看，论点标 [MM:SS]（1 次调用）
  • ④ 微观放大：仅动作类问题，对运动最强的引用时刻抽 12fps 中心放大逐帧分析
为什么微观层是视频特有的关键
一次甩枪只有 150–250 毫秒，1fps 的宏观帧必然漏掉。所以平时省着看（1fps），遇到"瞄准/动作/瞬间"类问题，自动对该时刻用 12fps + 中心放大重抽一遍——这是参考项目用真实 API 探针验证出的两级采样策略。
与 PDF 版的同构与差异
与 deepseek-v4-flash-vision-rag 是同构姊妹项目：同一模型、同一"卡片索引"思想、同一套 API 封装。PDF 版面向文档页（引用 [第N页]），视频版面向时间段（引用 [MM:SS]）；视频版独有两级采样 + 微观层自动升级 + 可播放片段回显，深读预算提升至 32768。

安装与配置

Python + ffmpeg，配好 API Key 即可开始看视频

1. 克隆项目

获取项目代码：

git clone https://github.com/liangdabiao/deepseek-v4-flash-vision-video-rag.git
cd deepseek-v4-flash-vision-video-rag
2. 准备依赖

需要 openai 库与 ffmpeg/ffprobe 在 PATH：

pip install openai
# 确认 ffmpeg / ffprobe 已安装并在 PATH 中
ffmpeg -version
ffprobe -version
3. 配置 API Key

API key 不内置在代码里（skill 可公开分发），二选一配置：

# 方式一：环境变量
export DEEPSEEK_API_KEY=your_key_here

# 方式二：写入本机文件（仅本机可见，首行即 key）
echo "your_key_here" > ~/.deepseek_api_key
4. 建索引（每份视频一次）

采样密度自动适配视频时长：

python scripts/ingest.py "比赛录像.mp4"
# 可选参数：--fps 2 / --limit-frames 30 / --force / --clean
5. 提问与查看

提问、定位时刻、切片段：

python scripts/ask.py "比赛录像.mp4" "第二次团战是怎么输的？"
python scripts/show.py "比赛录像.mp4" --at 01:23          # 该时刻帧
python scripts/show.py "比赛录像.mp4" --clip 01:20-01:30  # 可播放片段
python scripts/show.py "比赛录像.mp4" --micro 01:25       # 12fps 中心放大序列
6. 查看产出

产出文件在运行目录 video-vision-out/：

video-vision-out/
├── <名>_t0007.jpg       # 关键帧
├── <名>_clip0007.mp4    # 可播放片段
└── <名>_<问题>.html    # 自包含预览页（双击即看）

常见问题

关于 DeepSeek 视频视觉问答 RAG 的常见疑问

Q: 为什么不直接把视频文件传给模型？
A: 视觉模型没有"视频模态"。实测 GIF 只解码首帧（黑帧探针证实）；唯一正确方式是按时间顺序的 JPEG 帧序列 + prompt 声明时间轴。这就是本 Skill 存在的意义。
Q: 能分析声音吗？
A: 不能。模型只看画面，音轨会被忽略。音轨可用于本地定位（如枪声能量峰值），但"听到了什么"回答不了——我们会如实说明而不是编造。
Q: 事件时刻精确吗？
A: 宏观 1fps 的时间戳误差 ±2s；追问快速动作会自动升级 12fps 微观层（约 0.08s 粒度）；要绝对精确请直接播放切出的片段核对。
Q: 监控录像几小时怎么办？
A: 自动降到 0.1fps（10s/帧）建宏观索引，事件级问题仍可定位到分钟；关键时段用 --micro 或 show.py --clip 精查。超长视频建议分段 ingest。
Q: 和 PDF 版 skill 什么关系？
A: 同构的姊妹项目（同一模型、同一"卡片索引"思想、同一套 API 封装），一个面向文档页，一个面向视频时间轴。可以共存，触发词不同。
