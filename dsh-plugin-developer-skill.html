🔌 dsh 插件开发的痛点

DeepSeek Harness（dsh）采用"无特权内核、万物皆插件"的设计：模型适配器、工具注册表、Agent 循环、网页界面都是插件。给 dsh 增加新能力 = 写一个插件包挂到 Cordis 容器上，不需要 fork 源码。但插件开发存在诸多坑：必须用 Node 22+、宿主依赖要用 junction 链接不能手动 npm 装、npm install 顺序会清掉 junction、浏览器产物必须是单文件无动态 import、命令行跑通不算完还要 web 界面验收。这个 Skill 把"写一个 dsh 插件"做成一套可复用工作流，附带踩坑总结与参考案例。

关键环节说明

1. 诊断需求与选型
  • Tool 插件：让模型多一个可执行动作（90% 需求）
  • Skill 插件：教模型按规范产出
  • systemPrompt：引导模型何时用工具
  • Toolview：把工具结果画成好看界面
2. 环境准备与骨架生成
Node 必须 22+（dsh 0.1.x 与 tsdown 0.22 都依赖 Promise.withResolvers 等新 API）；运行 scaffold_plugin.py 自动生成骨架并替换占位符，对照 assets/examples 案例填充逻辑。
3. 双端构建与安装
junction 链 dsh 发布包里的 @deepseek-ai/*（不要手动 npm 装一份，版本会不一致）；npm install 会清掉 junction，link_deps.py 必须在 npm install 之后跑；安装用 dsh plugin --profile <名> add file:<绝对路径>。
4. 测试与验收
命令行跑通不算完，最终要在 web 界面（http://127.0.0.1:3080）看到工具调用 + 渲染效果。浏览器产物必须是单文件、无动态 import、无多 chunk、带 __ModuleLoader__ banner/footer。

安装与配置

简单几步，开始 dsh 插件开发之旅

1. 克隆项目

获取 Skill 代码：

git clone https://github.com/liangdabiao/dsh-plugin-developer-skill.git
cd dsh-plugin-developer-skill
2. 准备环境

Node 必须为 22+ 版本：

node --version   # 必须 v22.x 或更高
# 推荐用 fnm/nvm 管理 Node 版本
fnm install 22 && fnm use 22
3. 生成插件骨架

一键生成插件项目骨架，自动替换占位符：

python scripts/scaffold_plugin.py <目录> --name @scope/name
# 然后填充逻辑：工具/技能/系统提示/浏览器端
4. 安装依赖与链接宿主

注意顺序：先 npm install，再跑 link_deps.py：

npm install
# 然后链接 dsh 发布包里的 @deepseek-ai/* 依赖
python link_deps.py   # 必须在 npm install 之后跑
5. 双端构建

junction + tsdown 双端打包：

npm run build   # 生成浏览器端单文件产物
# 产物带 __ModuleLoader__ banner/footer
6. 安装进 profile 并验收

安装插件并在 web 界面验收：

dsh plugin --profile <名> add file:<绝对路径>
# 启动 dsh web 界面访问 http://127.0.0.1:3080
# 改代码后用 sync_profile.py 同步

常见问题

关于 dsh 插件开发 Skill 的常见疑问

Q: 为什么要强制 Node 22+？
A: dsh 0.1.x 与 tsdown 0.22 都依赖 Promise.withResolvers 等新 API，低于 22 版本会直接报错。这是硬约束，无法绕过。
Q: 为什么不能用 npm 直接装 @deepseek-ai/*？
A: 宿主依赖必须用 junction 链接 dsh 发布包里的 @deepseek-ai/*，手动 npm 装一份会导致版本不一致，运行时出错。
Q: npm install 之后为什么还要跑 link_deps.py？
A: npm install 会清掉 junction 链接，所以 link_deps.py 必须在 npm install 之后跑，重新建立与 dsh 发布包的依赖链接。顺序不能颠倒。
Q: 浏览器端产物有什么约束？
A: 浏览器产物必须是单文件、无动态 import、无多 chunk；必须带 __ModuleLoader__ banner/footer。违反任一约束会导致插件在 web 界面无法加载。
Q: 命令行跑通了就算完成吗？
A: 不算。最终验收要在 web 界面（http://127.0.0.1:3080）看到工具调用 + 渲染效果。命令行测试只是中间环节，web 界面验收才是交付标准。
