为什么是 LLM Wiki？

告别传统RAG，用AI构建真正的个人知识库

从 RAG 到知识编译器

传统RAG系统的完整链路：ingest → chunk → index → retrieve → rerank → prompt-pack → generate → cite。每次提问都要重新翻遍所有资料，效率低下。Karpathy指出，正确的做法是让AI当一个"知识编译器"——先把所有资料整理成一本结构清晰、彼此关联的百科全书，以后再提问直接翻这本百科书就行了。LLM Wiki就是实现这一理念的工具，它不仅解决了RAG的全部问题，还能一键生成wiki网站，成为真正的知识库。

三大核心能力

知识库构建 + 静态网站部署 + API对外服务

📚

LLM Wiki Skill

利用Claude Code的Skill机制，让AI自动完成知识库的采集、整理、质量控制和维护。支持初始化知识库、消化素材、批量处理、查询、深度分析、健康检查和知识图谱生成等7种工作流。
🌐

Quartz Wiki Skill

将生成的知识库通过Quartz v4发布为美观的静态网站。支持双向链接和关系图谱、全文搜索、响应式设计、亮色/暗色主题切换，可部署到Cloudflare Pages、Vercel或GitHub Pages。
🤖

Claude Agent SDK

通过Claude Agent SDK将知识库能力封装为可编程调用的AI Agent。支持CLI交互模式和基于FastAPI的HTTP服务，提供SSE流式响应和同步JSON响应两种API模式。

工作流程

支持7种工作流操作

init 初始化
→
ingest 消化素材
→
整理结构化
→
lint 健康检查
→
Quartz 发布
工作流 说明
init 初始化新知识库，创建目录结构和配置
ingest 消化单篇素材（URL / 文件 / 粘贴文本），自动提取实体和主题
batch-ingest 批量处理多文件（.md / .txt / .pdf / .html）
query 查询知识库，返回带来源引用的综合回答
digest 深度综合报告，跨素材分析特定主题
lint 健康检查：孤立页面、断链、内容质量
status 查看知识库状态：来源分布、页面统计、近期活动
graph 生成Mermaid知识图谱，可视化实体关系

知识库目录结构

清晰的结构化组织，便于管理和检索

目录结构
ai-wiki/
├── .wiki-schema.md      # 知识库配置和质量标准
├── index.md             # 内容索引
├── log.md               # 操作日志
├── overview.md          # 快速导航
├── raw/                 # 原始素材
│   ├── articles/        # 网页文章
│   ├── tweets/          # 推特内容
│   ├── wechat/          # 公众号文章
│   ├── xiaohongshu/     # 小红书内容
│   ├── zhihu/           # 知乎内容
│   ├── pdfs/            # PDF 文件
│   └── notes/           # 笔记和文本
└── wiki/                # 结构化 wiki 内容
    ├── entities/        # 实体页（工具、概念、人物）
    ├── topics/          # 主题页（研究领域）
    ├── sources/         # 来源摘要
    ├── comparisons/     # 对比分析
    └── synthesis/       # 综合分析

安装与配置

快速上手，构建你的个人知识库

1. 克隆项目

获取项目代码：

git clone https://github.com/liangdabiao/llm-wiki.git
cd llm-wiki
2. 安装依赖

创建虚拟环境并安装依赖：

python -m venv .venv
# Windows
.\.venv\Scripts\activate
# macOS/Linux
source .venv/bin/activate

pip install -r requirements.txt
3. 使用 LLM Wiki Skill（Claude Code）

在Claude Code中通过Skill机制操作知识库：

# 初始化知识库
> 利用 llm-wiki skill 对这些资料进行分析整理成wiki

# 生成Quartz静态网站
> 利用 quartz-wiki skill 把 ai-wiki 制作成 quartz网站
4. CLI模式运行Agent

通过Python脚本运行Claude Agent：

# 单次请求
python -B 7_wiki_writer.py -r "帮我写一篇关于 AI Agent 的综合文章"

# 交互式模式（连续对话）
python -B 7_wiki_writer.py -i
5. 启动API服务

基于FastAPI的HTTP服务：

# 直接启动
python -B wiki_writer_api.py

# 使用 uvicorn（支持热重载）
uvicorn wiki_writer_api:app --host 0.0.0.0 --port 8000 --reload
6. Quartz本地预览

本地预览wiki静态网站：

cd quartz
npx quartz build --serve

# 构建生产版本
npx quartz build

# 部署到 Cloudflare Pages
npx wrangler pages deploy public

API 接口

基于FastAPI的RESTful API服务

方法 路径 说明
GET /health 健康检查
POST /api/v1/wiki/generate 流式生成 (SSE)
POST /api/v1/wiki/generate/sync 同步生成 (JSON)
请求示例
# 同步模式
curl -X POST http://localhost:8000/api/v1/wiki/generate/sync \
  -H "Content-Type: application/json" \
  -d '{"request": "分析知识库中关于 Agent 的内容"}'

# 流式模式 (SSE)
curl -X POST http://localhost:8000/api/v1/wiki/generate \
  -H "Content-Type: application/json" \
  -d '{"request": "帮我消化这篇 https://example.com/article"}'

常见问题

关于LLM Wiki的常见疑问

Q: LLM Wiki和传统RAG有什么区别？
A: 传统RAG每次提问都要重新检索所有资料，而LLM Wiki先把资料整理成结构化的百科全书，提问时直接翻阅即可。这大幅提升了效率和准确性，是更本质的知识管理方式。
Q: 需要什么前置条件？
A: 需要安装Claude Code并配置Claude API密钥，Python 3.8+环境，以及Node.js（用于Quartz网站生成）。具体配置详见项目文档。
Q: 支持哪些素材源？
A: 支持网页文章、Twitter/X、微信公众号、YouTube视频、知乎、小红书、PDF文件和本地文件（.md/.txt）共8种素材源。
Q: 如何部署知识库网站？
A: 通过Quartz v4生成静态网站，支持部署到Cloudflare Pages、Vercel或GitHub Pages。也可本地预览和构建。
Q: API服务支持哪些模式？
A: 支持SSE流式响应（适合实时交互）和同步JSON响应（适合批量处理）两种模式。基于FastAPI构建，可轻松集成到其他系统中。
Q: 知识库如何保持质量？
A: 内置lint工作流，可自动检测孤立页面、断链和内容质量问题。同时通过.wiki-schema.md维护知识库的质量标准和配置。
